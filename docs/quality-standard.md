# 포트폴리오 코드 품질 평가 기준

이 점수는 이 저장소의 독해성과 유지보수성을 평가하기 위한 내부 코드 리뷰 척도입니다.
게임회사의 채용 기준이나 합격 확률, 산업 인증을 나타내지 않습니다.
자동 검사 결과와 독립 리뷰의 판단을 분리합니다. 테스트 개수·주석 개수·파일 길이로 점수를 계산하지 않습니다.

## 통과 조건

- 총점 98/100 이상, 각 항목군 80% 이상, 개별 항목 3/5 이상입니다.
- 해결되지 않은 정확성·메모리·소유권·설치/실행 차단 결함은 0건이어야 합니다.
- 서식·구조·Node 회귀, 재빌드한 Wasm, native Debug/Release CTest, 실제 브라우저 검사를 모두 통과합니다.
- 리팩토링 시 보존 기준선과 같은 입력을 재생하여 수치·토폴로지·진단값의 보존을 확인합니다.
  로컬 `build/portfolio-baseline/` 또는 `build/style-unification-baseline/` 자료가 필요한 비교는 공개 저장소의 일반 검사와 구분합니다.
- 빌드 캐시·SDK·node_modules를 제외한 별도 복사본에서 잠금 파일로 설치하고 검사합니다.
- 구현팀의 자가 점수만으로 완료하지 않습니다. 독립 검증팀이 지적 → 수정 → 재검토한 근거를 남깁니다.

## 항목별 배점과 확인 대상

모든 항목은 5점 만점입니다. 아래의 확인 대상을 실제 소스 경로·줄 번호와 실행 결과로 판정합니다.

| ID | 확인 대상 | 충분한 평가 근거 |
| --- | --- | --- |
| R1 | 코드 독해 경로 | README에서 app → JS 경계 → native 핵심까지 짧은 경로로 연결되고 실제 호출과 일치 |
| R2 | 이름·단위·상수 | 도메인 의미와 좌표/시간/거리 단위가 드러나며 수치 임계값의 목적 설명 |
| R3 | 함수 응집·중복·분기 | 한 논리 작업을 따라갈 수 있는 함수, 불필요한 추상화 없이 복잡한 분기 정리 |
| R4 | 핵심 알고리즘 | 갱신 순서·불변식·동률·퇴화·근사 한계의 이유를 코드와 설명으로 확인 |
| R5 | C++ 헤더와 API | 공개 계약, 전제·실패·반환값·참조 유효기간을 구현 전체를 읽지 않고 파악 |
| R6 | JS 실행 흐름 | 초기화·명령·고정 스텝·화면 갱신·정리 흐름과 오류 경로가 구분됨 |
| A1 | 모듈 책임과 의존 | simulation에서 DOM/렌더러 역참조 없음, domain에서 binding 구현 역참조 없음 |
| A2 | 소유권과 대여 수명 | RAII·컨테이너 소유, 비소유 참조·TypedArray 무효화 시점이 명시됨 |
| A3 | 명령 검증과 원자성 | 입력 검증 후 commit, 실패 시 기존 상태 보존, 내부 커널과 외부 편집 분리 |
| A4 | ABI와 생성 코드 | host 변환과 domain 분리, native/Wasm 소스 목록 공유, 생성물 재빌드 가능 |
| A5 | 확장 방식과 추상화 | 실제 변화 지점에 책임 배치, 목적 없는 계층·중복 상태·입자별 가상 호출 회피 |
| S1 | 경계와 실패 처리 | NaN·크기·빈 입력·0dt·퇴화 등 관련 경계의 의미 있는 회귀와 실패 계약 |
| S2 | 결정성과 수치 보존 | 시드·실행 순서·정밀도 계약과 이전 런타임 수치 비교 결과 |
| S3 | 회귀 검사 품질 | 실제 실패를 잡는 기대 동작, 입력 격리, 구현 복제에 그치지 않는 검증 |
| S4 | 자원과 생명주기 | 정상·부분 초기화 실패·프레임 실패·반복 dispose에 대한 정리 |
| B1 | 새 복사본에서 실행 | 잠금 의존성 설치, 로컬 절대 경로·기존 캐시 없이 문서 순서로 실행 |
| B2 | native/Wasm 빌드 | 버전·C++20·구성·산출물 경계와 Debug/Release·배포 Wasm 재빌드 근거 |
| B3 | 검증 자동화 | 공통 명령, 실패 시 비정상 종료, source fingerprint로 결과 노후화 감지 |
| P1 | 심사자 안내와 기여 경계 | 핵심 설계 판단·알고리즘 독해 동선·검증 한계·외부 자료 구분 |
| P2 | 저장소 위생과 사실성 | SDK/캐시/로컬 결과 제외, 외부 의존성 출처, 측정/미실행 주장 구분 |

## 0–5점 판단 척도

| 점수 | 판정 |
| --- | --- |
| 0 | 해당 계약 또는 근거가 없음 |
| 1 | 명백한 오류·오해·위험한 경로가 있음 |
| 2 | 큰 수정이 필요하며 독해 또는 유지보수를 방해함 |
| 3 | 기본 동작과 계약은 수용 가능하나 구체적인 보완점이 남음 |
| 4 | 근거가 충분하고 남은 보완이 작음 |
| 5 | 관련 코드·문서·의미 있는 검증이 일치하고 이번 범위에서 중요한 미해결점이 없음 |

점수는 리뷰 시점과 검토 범위에 한정됩니다. 높은 총점으로 낮은 항목군이나 차단 결함을 상쇄하지 않습니다.
실행하지 않은 sanitizer·정적 분석·성능·GPU·Windows EXE 검사를 통과한 것으로 표현하지 않습니다.

## 반복 작업과 재현

1. 프로젝트 팀이 위험·독해 장애를 실제 파일과 함께 기록하고 자가 평가합니다.
2. 다른 검증팀이 독립적으로 초기 점수와 지적을 기록합니다.
3. 팀이 수정하고 영향받은 단위/native 검사를 수행합니다.
4. 구현을 동결한 뒤 전체 실행 검사와 수치 비교, 새 복사본 설치 검사를 수행합니다.
5. 독립 검증팀이 `docs/portfolio-score.json`에 20개 판정·소스 근거·남은 한계를 기록합니다.
6. 최종 리뷰 후 `node tools/quality.mjs --seal`로 검토한 소스의 SHA-256을 기록합니다.
   이 명령은 점수를 올리거나 실행 검사를 대신하지 않습니다.

```powershell
npm run verify:portfolio    # SDK·C++ 도구·Chrome 필요: 재빌드→check→native Debug/Release→browser
npm run check:quality       # 독립 리뷰 점수·근거 파일·현재 소스 fingerprint 확인
npm run check:runtime       # C++ 원본과 배포 Wasm의 연결 확인, SDK 없이 실행
node tools/quality.mjs --execution  # 이번 소스의 전체 실행 결과까지 확인
# Boids/PBD: npm run verify:unification -- --baseline portfolio
# SPH: npm run verify:migration (보존 Python/native/Wasm 비교)
```

`npm run check`는 개발 중에도 실행할 수 있으며 리뷰 점수와 독립적입니다.
코드를 수정하면 `check:quality`는 기존 점수의 재사용을 거부합니다.
리뷰어는 변경 범위를 다시 검토하고, 동작 변경 시 해당 실행 결과도 갱신해야 합니다.
해시는 변조 방지 서명이 아니라 오래된 결과를 실수로 재사용하지 않도록 하는 검사입니다.
실행 로그와 `artifacts/portfolio-validation.json`은 로컬 생성물입니다.
공개 기록은 `docs/portfolio-review.md`와 `docs/portfolio-score.json`에 남깁니다.
소스 fingerprint는 텍스트 줄바꿈을 LF로 정규화하며 생성 Wasm·번들·검증 기록 자체는 제외합니다.
배포 Wasm의 검증은 `verify:portfolio`가 실제 재빌드하여 수행합니다.
실행 결과에는 별도 runtime fingerprint를 기록하므로 이후 Wasm·생성 로더·번들 변경도 `--execution`에서 거부합니다.
GitHub Actions 설정은 같은 공개 명령을 실행합니다. 업로드 전 로컬 검증과 원격 Actions 성공은 구분합니다.
공식 Actions는 저장소의 버전별 commit으로 고정합니다:
[checkout](https://github.com/actions/checkout), [setup-node](https://github.com/actions/setup-node),
[setup-python](https://github.com/actions/setup-python).
